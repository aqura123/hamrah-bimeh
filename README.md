# همراه بیمه (Hamrah Bimeh)

سامانه وب راست‌به‌چپ (RTL) فارسی برای مدیریت درخواست‌های خدمات بیمه‌ای رانندگان و لیست بیمه ماهانه کارگاه‌ها توسط دفتر خدمات بیمه‌ای **«همراه بیمه»**.

> **شفافیت حدود فعالیت سامانه:**
> این نرم‌افزار یک پرتال مدیریت درخواست‌های خدماتی دفتر است؛ مرجع رسمی تصمیم‌گیری بیمه‌ای نیست، درگاه پرداخت آنلاین ندارد، ثبت‌نام عمومی یا OTP پیامکی در نسخه اول ندارد و به سامانه `es.tamin.ir` متصل نیست. کارشناسان دفتر عملیات اجرایی را به‌صورت دستی خارج از این وب‌سایت انجام می‌دهد. به هیچ عنوان رمز عبور `es.tamin.ir` در این سامانه دریافت یا ذخیره نمی‌شود.

---

## ۱. معماری و فناوری‌ها (Stack)

- **زبان و چارچوب سرور:** Node.js 20 + TypeScript 5 (`strict`) + Express 4 + Helmet
- **پایگاه داده و ORM:** PostgreSQL + Drizzle ORM (`drizzle-orm`, `drizzle-kit`)
  - در محیط عملیاتی (Production): اتصال استاندارد از طریق `pg.Pool` با متغیر `DATABASE_URL=postgresql://...`
  - در محیط توسعه محلی یا بدون سرویس خارجی Postgres: موتور کامل PostgreSQL 16 تعبیه‌شده از طریق `@electric-sql/pglite` با مسیر `DATABASE_URL=pglite://./storage/pgdata`
- **اعتبارسنجی مشترک کلاینت و سرور:** Zod (`src/shared/validation.ts`)
- **امنیت احراز هویت و نشست‌ها:**
  - هش رمز عبور با الگوریتم **Argon2id** (`@node-rs/argon2`)
  - نشست‌های مدیریت‌شده در سرور (`sessions` با ذخیره هش `SHA-256` توکن کوکی، کوکی `HttpOnly`، محافظت CSRF با هدر `X-CSRF-Token` و بررسی `Origin`، محدودکننده نرخ تلاش ورود و قفل موقت حساب در برابر Brute-Force)
- **ذخیره‌سازی خصوصی فایل‌ها:** لایه انتزاعی `FileStorageProvider` (`src/server/services/storage.ts`) با کلیدهای مبهم UUID خارج از مسیر عمومی وب، تشخیص سمت سرور نوع واقعی فایل از روی Magic Bytes (`PDF`, `JPEG`, `PNG`, `WebP`) و دانلود صرفاً پس از بررسی مجدد مالکیت/نقش کاربری.
- **رابط کاربری:** React 18 + React Router 6 + Tailwind CSS با متغیرهای متمرکز برند همراه بیمه و فونت آزاد **وزیرمتن (Vazirmatn - OFL)**.

## ۲. متغیرهای محیطی (`.env`)

فایل `.env.example` را به `.env` کپی کرده و مقادیر واقعی را تنظیم کنید:

```bash
cp .env.example .env
```

| متغیر | توضیح | مقدار پیش‌فرض / نمونه |
|---|---|---|
| `NODE_ENV` | محیط اجرا (`development`، `test`، `production`) | `development` |
| `PORT` / `HOST` | پورت و آدرس اتصال سرور | `3000` / `0.0.0.0` |
| `DATABASE_URL` | رشته اتصال PostgreSQL یا مسیر PGlite محلی | `postgresql://...` یا `pglite://./storage/pgdata` |
| `SESSION_SECRET` | کلید تصادفی امن (حداقل ۳۲ کاراکتر؛ در `production` الزامی و بررسی شونده) | *(باید تغییر کند)* |
| `SESSION_TTL_HOURS` | مدت اعتبار نشست کاربری به ساعت | `12` |
| `PREVIEW_IFRAME_COMPAT` | سازگاری کوکی Partitioned برای پیش‌نمایش درون iframe (در `production` باید `false` باشد) | `false` |
| `FRAME_ANCESTORS` | سیاست CSP برای جلوگیری از Clickjacking در محیط عملیاتی | `'none'` |
| `BUSINESS_TIMEZONE` | منطقه زمانی رسمی نمایش تاریخ‌های شمسی | `Asia/Tehran` |
| `CURRENCY_UNIT` | واحد پولی واحد در کل سامانه (`TOMAN` یا `RIAL`) — هرگز ترکیب نمی‌شود | `TOMAN` |
| `INITIAL_PASSWORD_MODE` | سیاست رمز اولیه مشتریان جدید (`generated` یا `national_id`)؛ حالت تولیدشده امن‌تر است | `generated` |
| `INCOMPLETE_ALERT_HOURS` | آستانه ساعتی هشدار درخواست‌های تکمیل‌نشده برای دفتر | `72` |
| `PRIVATE_STORAGE_DIR` | مسیر خصوصی ذخیره فایل‌ها (خارج از پوشه‌های استاتیک عمومی) | `./storage/uploads` |
| `MAX_UPLOAD_MB` | حداکثر حجم مجاز هر فایل به مگابایت | `10` |
| `ALLOWED_UPLOAD_MIMES` | لیست سفید MIMEهای مجاز (بررسی با Magic Bytes سرور) | `application/pdf,image/jpeg,image/png,image/webp` |
| `ANTIVIRUS_MODE` | در نسخه فعلی اسکن آنتی‌ویروس پیاده‌سازی نشده است؛ فقط مقدار `disabled` پذیرفته می‌شود | `disabled` |
| `BOOTSTRAP_ADMIN_MOBILE` | شماره همراه مدیر اولیه دفتر جهت اسکریپت راه‌اندازی امن | `09120000000` |
| `BOOTSTRAP_ADMIN_PASSWORD` | رمز عبور قوی مدیر اولیه (حداقل ۱۰ کاراکتر) | *(باید تغییر کند)* |
| `PUBLIC_OFFICE_*` | اطلاعات تماس قابل پیکربندی دفتر (`TITLE`, `ADDRESS`, `PHONE`, `WORKING_HOURS`, `MAP_NOTE`) | جایگاه خالی تا زمان تنظیم دفتر |

## ۳. تصمیم‌های پیکربندی کسب‌وکار و ملاحظات امنیتی

1. **واحد پولی (`CURRENCY_UNIT`):** تمام مبالغ نهایی به‌صورت عدد صحیح به همراه واحد صریح (`TOMAN` به معنای تومان یا `RIAL` به معنای ریال) ذخیره و با برچسب روشن در رابط کاربری نمایش داده می‌شوند.
2. **سیاست رمز عبور اولیه (`INITIAL_PASSWORD_MODE`):**
   - حالت `generated` (پیش‌فرض پیشنهادی): رمز موقت تصادفی برای ارائه یک‌باره به مدیر ایجاد می‌شود و مشتری باید پیش از ورود به پرتال آن را تغییر دهد.
   - حالت `national_id` فقط با تصمیم آگاهانه مالک محصول قابل فعال‌سازی است: کد ملی معتبر مشتری به‌عنوان رمز اولیه استفاده می‌شود و تغییر آن در اولین ورود اجباری است؛ با توجه به نیمه‌عمومی‌بودن کد ملی، این روش برای محیط عملیاتی توصیه نمی‌شود.
3. **پروفایل راننده و کارگاه معرفی‌شده توسط مشتری:** هنگامی که مشتری در جریان ثبت درخواست، راننده یا کارگاه جدیدی معرفی می‌کند، آن پرونده بلافاصله زیرمجموعه حساب همان مشتری با وضعیت شفاف `pending_office_review` («ثبت‌شده توسط مشتری — در انتظار تطبیق دفتر») ذخیره می‌شود تا در ماه‌های بعد نیازی به ورود مجدد مشخصات ثابت نباشد؛ مسئول دفتر می‌تواند مشخصات را بررسی، ویرایش و به وضعیت `confirmed` تغییر دهد.
4. **ادامه کار هم‌زمان با انتظار اطلاعات مشتری:** وضعیت اصلی درخواست (`status`) از پرچم مستقل `awaiting_customer_info` جدا طراحی شده است تا دفتر بتواند درخواست را در وضعیت «در حال انجام» نگه دارد و هم‌زمان کسری مدرک را از مشتری پیگیری کند.

## ۴. دستورات نصب، مهاجرت پایگاه داده، اجرا و تست

```bash
# ۱. نصب وابستگی‌ها
npm install

# ۲. اجرای مهاجرت‌های پایگاه داده (PostgreSQL / PGlite)
npm run db:migrate

# ۳. ایجاد امن حساب مدیر دفتر (مناسب محیط عملیاتی و توسعه)
npm run db:bootstrap-admin

# ۴. (فقط محیط توسعه/دمو — غیرفعال در NODE_ENV=production) درج داده‌های آزمایشی فارسی
npm run db:seed

# ۵. اجرای سرور توسعه (پورت ۳۰۰۰ روی 0.0.0.0)
npm run dev

# ۶. بررسی فرمت، لینت، تایپ‌چک، تست‌های واحد/یکپارچه/امنیتی و بیلد نهایی
npm run lint
npm run typecheck
npm test
npm run build

# ۷. اجرای نسخه بیلدشده عملیاتی
npm start
```

## ۵. راهنمای استقرار، پشتیبان‌گیری و بازیابی (Backup & Recovery)

### الف) چک‌لیست پیش از استقرار عملیاتی (Production)
1. متغیر `NODE_ENV=production`، رشته اتصال PostgreSQL خارجی (`DATABASE_URL=postgresql://...`) و `SESSION_SECRET` تصادفی حداقل ۳۲ کاراکتری را تنظیم کنید.
2. اطمینان حاصل کنید `PREVIEW_IFRAME_COMPAT=false` است (سرور در حالت `production` در صورت فعال بودن این گزینه یا ضعیف بودن کلید نشست، به‌صورت خودکار از بالا آمدن جلوگیری می‌کند).
3. مقادیر واقعی تماس دفتر (`PUBLIC_OFFICE_ADDRESS`، `PUBLIC_OFFICE_PHONE`، `PUBLIC_OFFICE_WORKING_HOURS`) را در `.env` قرار دهید.
4. دستور `npm run db:migrate && npm run db:bootstrap-admin` را اجرا کنید (هرگز `db:seed` را در محیط عملیاتی اجرا نکنید).
5. پشت یک Reverse Proxy مجهز به TLS معتبر (HTTPS) مانند Nginx یا Caddy مستقر نمایید.

### ب) پشتیبان‌گیری (Backup)
1. **پایگاه داده PostgreSQL:** روزانه و پیش از هر به‌روزرسانی با `pg_dump` نسخه پشتیبان رمزنگاری‌شده تهیه کنید:
   ```bash
   pg_dump --format=custom --no-owner "$DATABASE_URL" > "backup-db-$(date +%F).dump"
   ```
2. **مخزن فایل‌های خصوصی (`PRIVATE_STORAGE_DIR`):** از پوشه فایل‌های خصوصی هم‌زمان با پایگاه داده نسخه پشتیبان رمزنگاری‌شده بگیرید تا کلیدهای `storage_key` ثبت‌شده در جدول `request_files` با فایل‌های فیزیکی همگام بمانند:
   ```bash
   tar -czf "backup-files-$(date +%F).tar.gz" -C "$(dirname "$PRIVATE_STORAGE_DIR")" "$(basename "$PRIVATE_STORAGE_DIR")"
   ```

### ج) بازیابی (Restore)
1. سرویس برنامه را متوقف کنید.
2. فایل‌های خصوصی را در مسیر `PRIVATE_STORAGE_DIR` با مجوز دسترسی محدود (`chmod 700`) بازیابی نمایید.
3. پایگاه داده را در یک دیتابیس تمیز بازیابی کنید:
   ```bash
   pg_restore --clean --if-exists --no-owner -d "$DATABASE_URL" backup-db-YYYY-MM-DD.dump
   ```
4. سلامت مهاجرت‌ها (`npm run db:migrate`) و مسیر `/api/health` را بررسی کرده و سرویس را مجدداً راه‌اندازی نمایید.
